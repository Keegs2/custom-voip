# tts — internal Piper text-to-speech sidecar (Visual IVR)

Contract: `docs/IVR_INTERFACES.md` §8.1. Plan: `docs/IVR_PRODUCT_PLAN.md` §5.4.

- **What:** renders IVR prompt text to WAV for the API (`services/ivr/tts.py`), which resamples to the canonical 8 kHz PCM16 prompt format and stores it in `ivr_prompt_audio`. Never on the call path: FreeSWITCH plays the stored WAV from its zone replica / local cache.
- **Where:** services VM only, `tts` service in `docker-compose.services.yml` (dev: `docker-compose.yml`). services-network only, **no published port**, no auth — the API (`IVR_TTS_URL=http://tts:5000`) is its only client.
- **API:** `POST /synthesize {text (1-1000 printable chars), voice}` → `audio/wav` at the voice's native rate (22.05 kHz mono 16-bit) | 400 | 503 (busy: no slot within `TTS_QUEUE_WAIT_S`, default 10 s); `GET /voices` → `[{id, label, gender, license, version}]` (`version` = engine + model hash, the API's render-cache key part — stripped before customers see the list); `GET /health`.
- **Server:** stdlib `ThreadingHTTPServer` (`server.py`), CPU onnxruntime, `TTS_CONCURRENCY` renders at once (default 2; Piper serialises its espeak-ng phonemizer internally). Text is never logged — length + output sha prefix only.
- **Voices (all public domain — checked 2026-10-25 in each MODEL_CARD at the pinned revision and on the author's page https://brycebeattie.com/files/tts/):** `en_US-ljspeech-medium` (female), `en_US-kristin-medium` (female), `en_US-norman-medium` (male) — trained from scratch on public-domain recordings (LJ Speech / LibriVox). Deliberately NOT used: voices fine-tuned from `lessac` (Blizzard research licence) or trained on CC BY-NC(-SA) data (ryan, hfc_*, l2arctic, kathleen ← ryan). Downloaded at BUILD time from `huggingface.co/rhasspy/piper-voices` at the revision in `voices.json`; every file's sha256 is verified (`fetch_voices.py`) — a mismatch fails the build. The running container never downloads.
- **Engine licence:** `piper-tts` (pinned `PIPER_VERSION` in the Dockerfile) is GPL-3.0-or-later and bundles espeak-ng (GPL-3.0). It runs unmodified as an internal network service and is not distributed (GPL, not AGPL) — flag it if the image is ever shipped to a third party.
- **Determinism:** Piper's VITS model samples noise, so two renders of the same text differ by a few samples. The API's render cache (`sha256(version|voice|text)` → stored sha, Redis + in-process) is what makes repeat text reuse one audio row; it is not bit-reproducible across cache misses.
- **Add / change a voice:** pick a model whose MODEL_CARD dataset licence allows commercial use AND that is not fine-tuned from a restricted base; add it to `voices.json` with `onnx_sha256` (the HF LFS oid) and the `.onnx.json` sha256; rebuild. Changing a model changes its `version`, so new renders get new cache keys (existing prompts keep their stored audio).
